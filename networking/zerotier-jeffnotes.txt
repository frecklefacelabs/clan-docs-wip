Clan gives you two ways to bring a machine into your ZeroTier network. Inventory machines -- defined in inventory.machines and assigned the peer role -- are fully managed by Clan: their identities, keys, and network membership are all generated and configured automatically. This is the approach for any machine you provision with clan machines install. External machines -- ones you don't manage with Clan, like a personal phone or a colleague's workstation -- can join the same network by adding their ZeroTier IPv6 address to the controller's allowedIps setting. These machines must have ZeroTier installed independently and join the network manually (using the network ID from clan vars get controller zerotier-controller/zerotier-network-id), but once the controller admits them, they participate in the mesh like any other peer.

? It's worth noting that allowedIps and the moon role solve different problems. allowedIps is about membership -- it tells the controller "this machine is allowed to join the network." A moon is about connectivity -- it provides a publicly reachable relay so that machines behind NAT or restrictive firewalls can find each other. An external machine admitted via allowedIps might still need the moon to connect if it's behind a strict NAT, and a moon does nothing about membership -- it just helps traffic flow. The two features are complementary: allowedIps opens the door, and the moon shows you how to walk through it.


 From a networking perspective, is it possible for me to simulate the laptop's likely scenario (such as sitting at a coffee shop) on EC2?

Yes! Put the laptop instance in a private subnet with a NAT gateway. That's almost exactly what a coffee shop looks like from a networking perspective:

- No public IP -- nothing can reach it directly
- Can make outbound connections (through the NAT gateway, just like a coffee shop router)
- ZeroTier's direct peer-to-peer hole-punching won't work -- the moon has to relay

The AWS setup would be:

+------------+---------+---------------------------------+--------------------------------------+
|  Machine   | Subnet  |            Public IP            |                 Why                  |
+------------+---------+---------------------------------+--------------------------------------+
| controller | public  | Elastic IP                      | Needs to be reachable to admit peers |
+------------+---------+---------------------------------+--------------------------------------+
| moon       | public  | Elastic IP                      | Needs to be reachable as a relay     |
+------------+---------+---------------------------------+--------------------------------------+
| laptop     | private | none (NAT gateway for outbound) | Simulates being behind NAT           |
+------------+---------+---------------------------------+--------------------------------------+

The catch: since the laptop has no public IP, you can't SSH into it directly from your admin machine to run clan machines install. You'd need to either:

1. Install it while it's in the public subnet first, then move it to private (easiest -- and honestly realistic, since you'd configure a real laptop at home before taking it to a coffee shop)
2. Use a bastion/jump host in the public subnet

Option 1 is simpler and makes a better docs narrative: "set up the laptop at the office, then take it to the coffee shop and it stays connected through the moon."

That said -- this adds real AWS complexity (VPC subnets, NAT gateway, moving instances) to what's supposed to be a ZeroTier guide. Worth it for the realism, or overkill for the docs?
